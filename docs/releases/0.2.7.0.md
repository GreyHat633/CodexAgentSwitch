# Codex Agent Switch 0.2.7.0

0.2.7.0 replaces Hook-driven context control with ownership-bound Managed Context Economy.

## Managed ownership boundary

- Context Economy is an automatic CAS capability for active projects with a valid applied configuration; it has no second project switch.
- Only tasks created from that project's CAS managed entry are eligible, including tasks rooted below the registered project directory.
- Project root, task path, thread ID, App Server session ID, connection instance, and ownership lease are validated before observation and immediately before native compaction.
- Lease drift, archived projects, invalid paths, restart ambiguity, persistence failures, and unproved thread state fail closed without stopping the user's completed turn.
- Ordinary, archived, and unapplied projects create no managed binding or Context Economy state.

## Event-driven Context Economy

- Uses official `thread/tokenUsage/updated`, `thread/status/changed`, `turn/*`, `item/*`, and approval lifecycle events.
- Realtime usage updates for one turn replace that turn's sample instead of inflating the turn history.
- Safe boundaries require an idle thread, a terminal Main turn, no pending approval, and no active tool or compaction item.
- Native compaction uses `thread/compact/start`; acknowledgement alone is not success. A same-thread `contextCompaction` started/completed lifecycle is required.
- Request ID and request/start/completed timestamps are persisted. An unresolved `Compacting` state after restart is blocked from automatic retry.
- Effectiveness continues to use 2-3 post-compaction samples and the existing cooldown policy.

## Hooks and Hard Gate

- CAS Hooks are `FrozenDisabled`; new project application does not generate CAS hook handlers.
- Historical ToolHost `--hook` invocations are explicit no-ops and do not contact Scheduler or write diagnostics.
- Hard Gate is disabled and removed from the production decision path.
- Registered-project cleanup preserves third-party hooks and creates a recoverable backup.

## Diagnostics

- Diagnostics project only managed identifiers, a fingerprinted canonical root, ownership/context state, token pressure, safe-boundary time, compaction timestamps, effectiveness, cooldown, and reason codes.
- Prompt text, model replies, source content, tool parameters, and Worker Result bodies are not persisted in managed diagnostics.

## Verification status

- Automated Core, Bootstrapper, Hook-freeze, ownership, negative-boundary, and Worker scheduling regressions pass.
- Real E-drive isolated acceptance observed official token updates and native `contextCompaction` started/completed events. SQLite reached `Effective` and `Cooldown` with an 83.8% input reduction; a same-process unmanaged task produced no managed binding or context state.
- Windows 125% DPI layout and original project-menu acceptance passed. Installer/ZIP manifests, required entries, versions, hashes, runtime signature, and C-drive release audit all passed; the release is GO. See `../acceptance/0.2.7.0/acceptance-report.md`.

## Upgrade and rollback

See `install-and-rollback.md`. Existing projects automatically gain the managed context capability once their applied configuration is valid. Before rolling back to 0.2.6.x, close active CAS tasks; keep the data backup created by Setup.
