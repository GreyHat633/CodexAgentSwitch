# Codex Agent Switch 0.1.11

本版本完成 0.1.10 未尽的「原生 Codex 模式真实 DeepSeek 子代理」链路，并修复了配置验证在 Codex 0.146 下失效的问题。不会改动已经正常工作的 CodexAgentSwitch 内置 DeepSeek 执行链。

## 一、修正 0.1.10 的错误收敛

0.1.10 曾把「项目级 config.toml 不能承载 Provider 定义」过度收敛为「原生 Codex 模式完全不支持外部 Provider Worker」，并把真实验证留给后续。本版本按官方 Codex 配置协议恢复为正确的分层：

1. **用户级 `CODEX_HOME/config.toml`**：注册 `model_providers.cas_*`（base_url、`wire_api = "responses"`），凭据通过 `auth.command` 指向随包分发的 `CodexAgentSwitch.CredentialBroker.exe`；API Key 仍保存在 Windows 凭据管理器，任何配置文件与项目目录都不含密钥。
2. **项目级 `.codex/config.toml`**：只写经过严格验证的白名单字段（主模型、推理强度、批准策略、沙箱策略、原生子代理默认项）；外部 Worker 仅声明 `[agents.cas_external_worker]` 角色并引用独立代理文件。
3. **代理文件 `.codex/agents/cas-external-worker.toml`**：`model = provider.ModelId`（如 `deepseek-v4-flash`）、`model_provider = cas_deepseek_default`。

原生模式不再通过「给 Terra 子代理改名为 deepseek」冒充接通；任何缺少真实 Provider/模型的伪标记都会被拒绝。

## 二、修复 Codex 0.146 项目信任门槛导致的配置验证失效

Codex 0.146 新增了「项目未被信任时不加载项目级 config」的门槛，导致写前严格校验静默失效。验证器现会在隔离的临时 `CODEX_HOME/config.toml` 中写入目标项目的 `[projects.'<路径>'] trust_level = "trusted"`，恢复真实的 `app-server --strict-config` 分层加载校验。

## 三、验证证据

- 完整解决方案 Release 构建 0 警告 0 错误；核心测试 98/98（含 `CAS_RUN_CODEX_CONFIG_E2E` 下两个真实 Codex 分层配置用例）。
- Codex CLI 0.146 能同时解析「用户级 DeepSeek Provider + 项目 `cas_external_worker` 角色 + 独立代理文件」；旧的 `model_provider = { ... }` 项目级非法表被精确拒绝（`invalid type: map, expected a string`）。
- CredentialBroker 能从已安装数据库 + Windows 凭据管理器取回真实 Key。
- 真实 DeepSeek 请求通过原生 Provider 链路成功：`model=deepseek-v4-flash`、`provider=cas_deepseek_default`、返回 `OK`、用量 10,737 tokens。
- 运行时子代理派生证据（CodexAgentSwitch 侧会话）：`cas_external_worker` 子代理被真实创建，`agent_role=cas_external_worker`、`model_provider=cas_deepseek_default`，返回 `NATIVE_DEEPSEEK_SUBAGENT_OK: 42`。

## 四、已知边界（如实记录）

- 「OpenAI 主代理（Sol/Terra/Luna）→ DeepSeek 子代理」的最终运行时场景**待 OpenAI 用量额度重置后补验**（当前账号额度于 2026-08-04 触顶，提示 08-09 后可重试）。子代理机制本身已用 DeepSeek 主线程证明可用。
- DeepSeek `/models` 端点返回 `{"object":"list","data":[...]}`，与 Codex 期望的 `{"models":[...]}` 不同，会触发模型元数据回退警告；不影响真实请求。后续版本可考虑在 Provider 配置中显式声明模型元数据。

Windows 10 22H2 x64 仍是主验收环境；升级不会覆盖现有 Profile、Provider 或凭据。
