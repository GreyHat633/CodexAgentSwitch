# Codex Agent Switch 0.2.6

## Lower Main orchestration tax

- Repartition triggers now queue and coalesce per task group and working directory. One valid ownership decision clears the matching pending set while retaining trigger telemetry.
- The Hard Gate still denies recognized mutations while ownership is unresolved, preserves Worker-owned lease protection, and leaves unrelated working directories unaffected.
- Successful preflight and repartition responses are compact; delayed tool definitions are cached for the ToolHost process lifetime.
- Deterministic adopted packages complete without a redundant standalone completion handshake. Ambiguous packages stay conservative.
- Managed AGENTS policy has one semantic source and was reduced from about 1,160 to 463 estimated tokens while retaining the eight lifecycle triggers, MAIN/WORKER ownership, non-duplication, review, and adoption rules.

## External Worker runtime

- External Workers use configurable 24/48 soft limits, 8/16 silent lease increments, and 64/128 hard caps by default.
- Each External task snapshots its configured monetary, token, and request budget. Usage-unavailable or currency-mismatched cost remains explicitly unverified while other mechanical safety limits continue.
- Repeated identical tool calls, wall clock, cancellation, provider turns, tool calls, and configured budgets remain hard stops.
- Tool output carried forward is bounded. A hard stop may make one no-tools finalization request only when request, token, monetary, and time safety still permit it.
- Result telemetry includes turns, tool calls, lease extensions, hard-limit reason, configured budget snapshot, cost verification, finalization state, and changed files.
- Native Luna continues to use the existing `spawn_agent` path and does not consume External runtime leases.

## Validation status

- Targeted tests cover pending/coalesced repartition behavior, the Hard Gate, deterministic package completion, compact managed policy, External soft extension, hard turn/tool stops, user-variable monetary budgets, usage-unavailable behavior, no-tools finalization, and Native isolation.
- Release build, package manifest, ZIP contents, installer signature, and SHA-256 checks are performed by the 0.2.6 packaging workflow.
- Real-provider acceptance remains a separate verdict and must not be inferred from fake-provider or build evidence.
