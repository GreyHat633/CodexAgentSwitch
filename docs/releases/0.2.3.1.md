# Codex Agent Switch 0.2.3.1

0.2.3.1 is a focused update on top of 0.2.3. It adds the missing delegation-capability gate for natural development requests and introduces OpenCode Zen as an external provider without changing the existing eight repartition triggers.

## Changes

- Managed project instructions now require a Delegation Capability Preflight after minimum localization and before the first substantive implementation package.
- If delayed-loaded Agent Switch scheduling tools are available, Main must perform the Initial Delegation Check; if they are unavailable, Main records `WORKER_CAPABILITY_MISSING` and continues without deadlock.
- Micro tasks remain exempt, and the preflight is explicitly not a ninth repartition trigger.
- Added the `OpenCodeZen` provider kind and built-in `opencode-zen` preset.
- Models are refreshed dynamically from `https://opencode.ai/zen/v1/models`; the selected raw model ID is persisted and is never silently replaced when it disappears from the refreshed catalog.
- External execution uses the installed OpenCode CLI as the protocol bridge and invokes the selected model as `opencode/<model-id>`.
- The provider UI supports model refresh, selection persistence, CLI/login validation, and explicit missing-model diagnostics without storing a second API credential.
- Product and packaging version metadata now use `0.2.3.1`.

## Compatibility

- Existing DeepSeek provider behavior remains covered by regression tests.
- Existing scheduler, external runtime, and the closed set of eight repartition triggers are unchanged.
- OpenCode Zen requires an `opencode` executable on `PATH` and an existing OpenCode login.
