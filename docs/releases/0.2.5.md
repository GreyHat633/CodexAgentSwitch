# Codex Agent Switch 0.2.5

## Deterministic delegation preflight

- Delegation now resolves Git worktrees to the canonical project, then mechanically resolves the Applied Profile and Worker Role before dispatch.
- Preflight returns precise project, profile, worker-policy, and native-capability reason codes without invoking a model.
- Native `cas_luna_worker` registration remains separate from the official Codex `spawn_agent` call, and Main must not duplicate work while the Worker is active.

## Main Context Economy

- The real `source=vscode` Stop-hook path now feeds the production Context Economy coordinator instead of relying only on `ControlledTaskService`.
- Native JSONL `last_token_usage.input_tokens` and `model_context_window` take priority over estimates. Structured `type="compacted"` events are tracked without scanning conversation text.
- Agent Switch compact requests stay on the same Main thread and never create Main B/Main C. `AutoRollover` remains disabled.
- Default pressure bands are 40% Observe, 55% Candidate, 65% Mandatory Pending, and 75% Hard Protection.
- Host-automatic and Agent Switch-triggered compaction share one verification/cooldown lifecycle, including duplicate suppression, deferred post baselines, restart recovery, and ineffective/failure protection.
- Diagnostics and SQLite state now retain compaction trigger, native pressure/input, structured timestamp, effectiveness, and cooldown state.

## Validation status

- Directed Context Economy and VSCode production-path tests pass in the release worktree.
- Release build, package manifest, and SHA-256 checks are performed by the 0.2.5 packaging workflow.
- Live acceptance is intentionally separate: after installing 0.2.5, a real Codex Main task must still confirm production triggering, same-thread compaction, post-compact reduction, cooldown, and Worker dispatch with the installed ToolHost.
